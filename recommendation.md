For production, separate the crawler, indexer, and query services so each can scale independently and be deployed with clear SLOs. The crawler should include per-host politeness policies, retry strategies, and a robust URL frontier service backed by a durable queue with checkpoints. The indexer should push results into a dedicated search store optimized for query workloads, and the search service should read from an immutable or near-real-time index to minimize tail latency and avoid write contention. The current event-stream model is a good local foundation; in production, promote it to a durable fan-out path so operators and downstream consumers can watch indexing progress without coupling directly to the crawler process.

Operationally, add observability across the crawl pipeline (queue depth, fetch rate, error rates), and isolate untrusted content processing with sandboxing. Ingestion should enforce compliance policies, and storage should include retention policies and auditing. Finally, add deployment automation, canary rollouts, and capacity-based backpressure to manage spikes in crawl traffic and search usage. If concurrency expands beyond a single-process event loop, evolve the current async-mutex guarded frontier into a process-safe queue or lease-based worker model with stronger ownership and cancellation semantics.
