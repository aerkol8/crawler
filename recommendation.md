For production, separate the crawler, indexer, and query services so each can scale independently and be deployed with clear SLOs. The crawler should add per-host politeness policies, retry strategies, robots-aware admission rules, and a durable frontier abstraction with checkpoints or leases. The indexer should push results into a search-optimized store, while the query service should read from an immutable or near-real-time index to keep latency stable as crawl traffic grows. The current SSE-based live visibility is a strong localhost foundation; in production, that same stream should be promoted into a durable fan-out path for operators, dashboards, and downstream consumers.

Operationally, add observability across the crawl pipeline, including queue depth, fetch rate, per-host saturation, indexing lag, and error budgets. Isolate untrusted content handling with sandboxing, enforce compliance and retention policies, and add deployment automation with canary rollouts. If concurrency expands beyond a single-process event loop, evolve the current async-mutex guarded frontier into a process-safe queue or lease-based worker model with stronger ownership, cancellation, and recovery semantics so the concurrency guarantees remain explicit even after scaling out.
